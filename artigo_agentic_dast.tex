% Resumo e Abstract

\begin{abstract}
Ferramentas de \textit{Dynamic Application Security Testing} (DAST)
tradicionais são incapazes de navegar os estados internos de
\textit{Single Page Applications} (SPAs) ou de detectar vulnerabilidades
que exigem compreensão semântica, como Lógica de Negócio (BLV),
XSS armazenado via campos dinâmicos, ataques a JWT e exposição de dados
sensíveis. Este artigo propõe o \textbf{Agentic DAST}, um
\textit{framework} que integra raciocínio semântico de Grandes Modelos
de Linguagem (LLMs) com automação de navegadores via Puppeteer e padrão
Screenplay, operando em um \textit{loop} ReAct autônomo. O
\textit{framework} é estruturado em quatro módulos: Percepção (extrator
DOM via CDP), Cognitivo (agente LLM com \textit{loop} ReAct), Executor
(Screenplay + Puppeteer com \textit{Abuse Cases} predefinidos) e Auditoria
(OWASP ZAP \textit{daemon}). A validação empírica será conduzida sobre o
OWASP Juice Shop em experimento comparativo com três cenários, avaliando
\textit{Recall}, \textit{Precision} e F1-\textit{Score} na detecção de
múltiplas categorias de vulnerabilidades. Espera-se demonstrar superioridade
estatisticamente significativa do Agentic DAST frente ao OWASP ZAP tradicional.

\bigskip\noindent
\textbf{Palavras-chave:}
DAST, Single Page Application, LLM, Vulnerabilidade de Lógica de Negócio,
XSS, JWT, ReAct, Screenplay Pattern, OWASP Juice Shop.
\end{abstract}

\selectlanguage{english}
\begin{abstract}
Traditional Dynamic Application Security Testing (DAST) tools fail to
navigate the internal states of Single Page Applications (SPAs) or to
detect vulnerabilities requiring semantic understanding, such as Business
Logic Vulnerabilities (BLVs), stored XSS via dynamic fields, JWT attacks,
and sensitive data exposure. This paper proposes \textbf{Agentic DAST},
a framework that integrates semantic reasoning from Large Language Models
(LLMs) with browser automation via Puppeteer and the Screenplay Pattern,
operating within an autonomous ReAct loop. The framework comprises four
modules: Perception (DOM extractor via CDP), Cognitive (LLM agent with
ReAct loop), Executor (Screenplay + Puppeteer with predefined Abuse Cases),
and Audit (OWASP ZAP daemon). Empirical validation will be conducted on
OWASP Juice Shop through a three-scenario comparative experiment, evaluating
Recall, Precision, and F1-Score across multiple vulnerability categories.
The results are expected to demonstrate statistically significant superiority
of Agentic DAST over traditional OWASP ZAP.

\bigskip\noindent
\textbf{Keywords:}
DAST, Single Page Application, LLM, Business Logic Vulnerability,
XSS, JWT, ReAct, Screenplay Pattern, OWASP Juice Shop.
\end{abstract}

\section{Introdução}
% =============================================================

As aplicações web contemporâneas migraram progressivamente para o
paradigma das \textit{Single Page Applications} (SPAs). \textit{Frameworks}
como Angular, React e Vue.js promoveram uma inversão arquitetural na
qual toda a navegação é controlada por JavaScript no lado do cliente,
com conteúdo injetado dinamicamente no DOM por chamadas assíncronas a
APIs \cite{stackhawk2024, getastra2024}.

Essa evolução criou uma lacuna crítica nas metodologias de testes
dinâmicos de segurança. Ferramentas DAST consolidadas, como o OWASP
ZAP, utilizam \textit{crawlers} que analisam estaticamente o HTML em
busca de âncoras \texttt{<a>} para mapear a superfície de ataque
\cite{brightsec2024}. Diante de uma SPA, esses \textit{scanners}
percebem uma única página opaca, sem capacidade de explorar os estados
internos da aplicação.

Vulnerabilidades de Lógica de Negócio (BLVs) decorrem de falhas no
\textit{design} dos processos, e não de erros de codificação de baixo
nível \cite{portswigger2024}. Exemplos incluem: manipulação de preço
via API, IDOR (\textit{Insecure Direct Object Reference}), acesso a
rotas administrativas sem privilégios e abuso de condições de corrida
em fluxos de pagamento. Detectar tais falhas exige compreensão do
domínio da aplicação, algo estruturalmente impossível para ferramentas
baseadas em correspondência de padrões \cite{karadbhajne2025}.

LLMs com capacidades avançadas de raciocínio introduzem uma nova via
para o problema. O padrão ReAct (\textit{Reasoning + Acting})
\cite{yao2023react} demonstrou que LLMs podem alternar entre raciocínio
e execução de ações de forma iterativa, comportamento diretamente
aplicável à exploração autônoma de aplicações web.

Este trabalho propõe o \textbf{Agentic DAST}, um \textit{framework} que
integra raciocínio semântico de LLMs com automação de navegadores via
Puppeteer e padrão Screenplay, com o objetivo de superar
estatisticamente as ferramentas DAST tradicionais na detecção de BLVs
em SPAs. A questão central de pesquisa é:

\begin{quote}
\small\textit{Em que medida um framework de DAST baseado em agente
autônomo LLM, orquestrando um navegador headless via padrão Screenplay,
supera ferramentas tradicionais de DAST na detecção de vulnerabilidades
de lógica de negócio em SPAs?}
\end{quote}

\section{Trabalhos Relacionados}
% =============================================================

\subsection{DAST em SPAs}

A literatura científica sobre DAST para SPAs é escassa e
concentra-se predominantemente na caracterização das limitações de
ferramentas existentes \cite{brightsec2024, stackhawk2024}, sem propor
artefatos que as superem de forma empiricamente mensurável. O
\textit{Chrome DevTools Protocol} (CDP) provê uma interface de baixo
nível com o motor Chromium via WebSockets, permitindo intercepção de
rede em tempo real com granularidade inacessível ao Selenium WebDriver
\cite{lightpanda2024} --- tornando o Puppeteer o instrumento ideal para
testes de segurança ofensiva.

\subsection{LLMs Agênticos e Padrão ReAct}

\citeonline{yao2023react} introduziram o padrão ReAct, no qual o LLM
intercala passos de raciocínio (\textit{thought}), ações executáveis
(\textit{action}) e observações do ambiente (\textit{observation}),
produzindo trajetórias de decisão interpretáveis.
\citeonline{wei2022chain} demonstraram que \textit{Chain-of-Thought
prompting} habilita LLMs a resolver problemas de múltiplas etapas.
Esses paradigmas formam a base algorítmica do Módulo Cognitivo do
Agentic DAST.

\subsection{Fuzzing Semântico}

\citeonline{yang2025hybrid} demonstraram que LLMs com \textit{constraint
solving} podem gerar \textit{payloads} que cobrem caminhos de execução
profundos inacessíveis a \textit{fuzzers} por mutação aleatória.
O \textit{Semantic Fuzzer} do Agentic DAST aplica esse princípio ao
contexto de campos de formulário em SPAs.

\section{Framework Proposto}
% =============================================================

\subsection{Visão Geral da Arquitetura}

O Agentic DAST é estruturado em quatro módulos com responsabilidades
bem definidas, conforme ilustrado na Figura~\ref{fig:arquitetura}.

\begin{figure}[htb]
\centering
\small
\begin{verbatim}
 DOMExtractor        ReActAgent
 (Percepção)   -->   (Cognitivo)
      |                   |
      v                   v
   AppMap         ActionDispatcher
                   (Executor)
                       |
                   BrowseTheWeb
                   HttpClient
                   OWASP ZAP
                   (Auditoria)
\end{verbatim}
\caption{Arquitetura de quatro módulos do Agentic DAST.}
\label{fig:arquitetura}
\end{figure}

O fluxo de execução ocorre em quatro fases sequenciais: (1)
\textit{Percepção}: o DOMExtractor navega pela SPA e constrói o
\textit{AppMap}; (2) \textit{Executor}: o \textit{ActionDispatcher}
inicializa o Actor; (3) \textit{Cognição}: o \textit{ReActAgent} executa
o \textit{loop} ReAct com o LLM; (4) \textit{Relatório}: os
\textit{Findings} são salvos em JSON.

\subsection{Módulo de Percepção}

Implementado com Puppeteer, o \textit{DOMExtractor} navega pelas rotas
Angular do OWASP Juice Shop e constrói o \textit{AppMap} — objeto
estruturado que resume: rotas visitadas com formulários e seletores CSS,
chamadas HTTP interceptadas via CDP, tokens JWT coletados por login
automatizado e metadados da aplicação. O tráfego é roteado pelo proxy
OWASP ZAP para auditoria passiva simultânea.

\subsection{Módulo Cognitivo}

O \textit{ReActAgent} implementa o \textit{loop} ReAct sobre a API
Claude (Anthropic). O SYSTEM\_PROMPT define ao LLM: seu papel como
pesquisador de segurança, as sete categorias de BLVs a investigar e as
oito ações disponíveis. O \textit{Prompt Caching} da Anthropic
armazena o SYSTEM\_PROMPT em cache entre iterações, reduzindo custo em
até 90\%. O histórico de conversa cresce a cada iteração: AppMap
inicial, seguido de ciclos (\textit{thought} + \textit{action}) /
\textit{observation}.

\subsection{Módulo Executor}

Implementado com o \textit{Screenplay Pattern}
\cite{serenityscreenplay}, compõe-se de três camadas: \textit{Actor}
(agente de segurança com habilidades), \textit{Abilities}
(\texttt{BrowseTheWeb} via Puppeteer e \texttt{HttpClient} via Axios)
e \textit{ActionDispatcher} (mapeia \texttt{ParsedAction} → Ability
correta). As ações disponíveis ao LLM são: \texttt{navigate},
\texttt{fill\_field}, \texttt{click\_element}, \texttt{read\_page},
\texttt{make\_request}, \texttt{extract\_tokens},
\texttt{report\_finding} e \texttt{finish}. O JWT extraído é
propagado automaticamente para o \texttt{HttpClient}.

\subsection{Módulo de Auditoria}

O OWASP ZAP opera em modo \textit{daemon} como proxy reverso.
Durante a fase de Percepção, todo o tráfego do browser é roteado pelo
ZAP, que registra passivamente a superfície de ataque. Após o
\textit{loop} ReAct, o ZAP executa varredura ativa guiada pelos
\textit{endpoints} descobertos semanticamente, enriquecendo os
\textit{findings} com detecções de vulnerabilidades técnicas
complementares.

\section{Metodologia}
% =============================================================

A pesquisa adota \textbf{Design Science Research} (DSR)
\cite{hevner2004design}, combinando o desenvolvimento de um artefato
tecnológico com geração de conhecimento científico rigoroso sobre sua
eficácia. O projeto está dividido em sete fases ao longo de 36 semanas
(TCC~I: Fases 1--3; TCC~II: Fases 4--7).

\subsection{Protocolo Experimental}

O experimento comparativo (Fase~6) avalia três cenários sobre o OWASP
Juice Shop \cite{owaspjuiceshop}, com três rodadas cada ($n = 3$):

\begin{itemize}\setlength{\itemsep}{2pt}
  \item \textbf{Cenário A} — OWASP ZAP com \textit{spider} padrão
  (\textit{baseline} tradicional);
  \item \textbf{Cenário B} — OWASP ZAP guiado por suíte E2E
  pré-gravada (\textit{baseline} E2E);
  \item \textbf{Cenário C} — Agentic DAST em modo \textit{black-box}
  autônomo (experimental).
\end{itemize}

O banco de dados do Juice Shop é reinicializado entre rodadas para
garantir estado inicial idêntico. A análise estatística utiliza o teste
de Wilcoxon para amostras emparelhadas ($\alpha = 0{,}05$).

\subsection{Hipóteses Testáveis}

\begin{description}\setlength{\itemsep}{2pt}
  \item[\textbf{H1}] $\text{Recall}(C) > \text{Recall}(A)$
  com significância estatística ($p < 0{,}05$).
  \item[\textbf{H2}] $\text{Endpoints}(C) > \text{Endpoints}(A)$
  e $\text{Endpoints}(C) > \text{Endpoints}(B)$.
  \item[\textbf{H3}] A taxa de detecção do \textit{Semantic Fuzzer}
  é superior à do \textit{fuzzing} aleatório sobre os mesmos campos.
\end{description}

\subsection{Métricas de Avaliação}

\begin{table}[htb]
\centering
\caption{Métricas do experimento comparativo.\label{tab:metricas}}
\small
\begin{tabularx}{\columnwidth}{lX}
\toprule
\textbf{Métrica} & \textbf{Definição} \\

  $\text{VP} / (\text{VP} + \text{FP})$ \\

A Matriz de \textit{Ground Truth} será construída a partir do catálogo
oficial de vulnerabilidades do OWASP Juice Shop, garantindo gabarito
confiável e reduzindo viés de seleção.

\subsection{Ameaças à Validade}

\textbf{Interna:} variações entre rodadas causadas pela natureza
probabilística dos LLMs serão controladas com temperatura fixa
($T = 0{,}3$) e mesma versão de modelo.
\textbf{Externa:} os resultados são válidos para o Juice Shop; a
generalização para sistemas reais será avaliada em ambiente de
\textit{staging} corporativo.
\textbf{Construção:} a Matriz GT é derivada do catálogo oficial OWASP,
eliminando subjetividade na definição de BLVs.

% =============================================================
\section{Conclusão}
% =============================================================

Este artigo apresentou o Agentic DAST, um \textit{framework} que
endereça a lacuna crítica entre as capacidades das ferramentas DAST
tradicionais e as demandas de segurança de SPAs modernas. A integração
de raciocínio semântico de LLMs com automação de navegadores via padrão
ReAct e Screenplay representa uma mudança de paradigma: de testes
baseados em padrões sintáticos para testes guiados por compreensão do
domínio. A implementação dos módulos de Percepção, Cognitivo e Executor
está em andamento sobre o OWASP Juice Shop, com os experimentos
comparativos previstos para o segundo semestre de 2026. Os resultados
têm potencial de impactar diretamente \textit{pipelines} de DevSecOps
na indústria brasileira e de contribuir com a literatura científica sobre
DAST agêntico em SPAs.
